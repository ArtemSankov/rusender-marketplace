# Тестовая сборка: модули 1–4

Обрезанная версия курса «RuSender через чат» — только первые четыре модуля, чтобы прогнать их
вживую и посмотреть, как оно работает.

## Запуск

```bash
cd <папка проекта>
claude
```

Дальше в чате:

```
/rusender-course 1
```

Или сразу с любого другого: `/rusender-course 2`, `3`, `4`. Без номера — продолжит с того места, что записано в `course-state.md`, или начнёт с первого. Модули не блокируют друг друга —
если файла состояния нет, каждый сам делает короткую разведку.

## Что внутри

| Модуль | Тема | Сколько занимает |
|---|---|---|
| 1 | Подключение MCP + эксперимент со временем | до 15 минут |
| 2 | Состояние аккаунта: сначала угадай, потом покажу | 15 минут на рабочем аккаунте, 2 на пустом |
| 3 | Домен и почтовый ящик на нём — записи одним списком | 20 минут + ожидание DNS |
| 4 | Письмо, реальная отправка себе, проверка спам-фильтром | 30 минут |

Все семь скиллов RuSender внутри, ставить ничего не нужно.

> ⚠️ **Модуль 4 отправляет настоящее письмо** — на адрес, который ты назовёшь, плюс на адрес
> сервиса проверки. Перед запуском будет двойное подтверждение.

## Что проверять — в `TESTING.md`

Там чек-лист по каждому модулю: что должно произойти, где вероятнее всего сломается и что пока
вообще не проверялось.

## Чем эта сборка отличается от полной

- Только модули 1–4. Модуль 4 заканчивается словами «тестовая сборка закончилась», а не переходом
  в пятый
- Всё остальное — тот же код, те же правила, те же скиллы

## Файлы, которые появятся по ходу

`course-state.md` (модуль 2), `client-profile.md` (модуль 3), `email-draft.html` (модуль 4),
`dns-records.md` (модуль 3, не всегда). В них твои данные — если будешь передавать папку, удали.
